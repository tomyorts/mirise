# 06. GEO/SEOプレイブック(AI検索に引用されるための実装手順)

目的: Google検索(AI Overview / AIモード含む)、ChatGPT、Perplexity等が矯正関連の質問に答えるとき、
本メディアが**引用元・参照元として選ばれる**状態を作る。順位ではなく「引用シェア」を取りに行く。

## 1. 引用される文章の型(全ライター必修)

AIが引用するのは「そのまま切り出して答えになる段落」。各H2セクションを以下の順で書く。

```
① 定義文    「顎変形症とは、上下の顎の骨格的なずれにより噛み合わせと顔貌に
              問題が生じている状態を指します。」
② 条件分岐  「歯の位置だけの問題(歯性)であれば矯正単独で、骨格のずれが
              大きい場合(骨格性)は外科手術の併用が選択肢になります。」
③ 数字      「外科矯正の全体期間はおおむね2〜3年、入院は1〜2週間程度です。」
④ 出典      (日本矯正歯科学会◯◯ガイドライン、20XX)
```

- 1段落=1主張。「〜ですが、〜で、〜なので」の長文連結はAIに切り出されない
- 代名詞を減らす。「この治療は」→「サージェリーファーストは」(段落単体で意味が通る=引用可能)
- 比較・条件は必ず表にする(表はAI Overviewへの採用率が高い)
- リード文の要約3〜5行は「その記事への質問に対する完結した答え」として書く

## 2. FAQマイニング(一次データの武器化)

1. カウンセリング記録・LINE・電話で実際に来た質問を週次で収集(個人情報を除去し質問文だけ抽出)
2. 質問文をほぼそのままFAQページのH1/questionにする(患者の言葉=検索・AIチャットの言葉)
3. 回答は1の型で150〜300字+詳細記事へのリンク
4. これは「患者の生の質問データベース」であり、検索ボリュームツールに出ない需要を先回りできる競合非対称の資産

## 3. エンティティ確立(誰が言っているかの証明)

- 院長・監修医の `Physician` スキーマ + researchmap・学会サイト・公式サイトプロフィールを `sameAs` で相互リンク
- メディア(Organization)⇔医院(MedicalClinic)⇔人物(Physician)の三者をJSON-LDで接続(02章3節)
- 学会発表・論文が出るたびに、対応する患者向け記事を書き相互参照(「この記事の内容は◯◯学会で発表した△△に基づく」)
- Wikipedia的な第三者言及は狙って作れないが、**学会・大学・報道からの被リンクは狙える**: プレスリリース(デジタル矯正・サージェリーファーストの症例報告)、専門誌への寄稿、学会サイトの医院検索登録を整備

## 4. マルチモーダル展開

- 柱記事にはYouTube動画(院長本人が3〜8分で解説)を埋め込む。動画は本人性・実在性の最強の証明であり、AIモードは動画ソースも参照する
- 図版(術式フロー図、保険適用の判断フローチャート、3Dシミュレーション画面)は自前作成+altテキスト・キャプションを丁寧に(画像検索・AI画像理解経由の流入)
- 音声(ポッドキャスト)は12か月ロードマップのPhase 2で判断(工数対効果を見る)

## 5. 技術チェックリスト

- [ ] `llms.txt` を設置(主要記事とサイト構造の案内)— 効果は未確定だがコスト極小
- [ ] GPTBot / ClaudeBot / PerplexityBot / Google-Extended を**ブロックしない**(robots.txt方針として明文化。引用されることが戦略)
- [ ] XMLサイトマップ+更新日の正確な反映(lastmod を実際の更新時のみ変更。嘘のlastmodは信頼を落とす)
- [ ] 全記事に `dateModified` と「何を更新したか」の表示(鮮度シグナル)
- [ ] タイトル・H1は質問文または結論文(「〜について」「〜まとめ」は禁止)
- [ ] 内部リンクは「文脈アンカー」(「こちら」禁止、リンク先の内容が分かる文言)

## 6. 引用モニタリング(月次・手動)

GEOの計測ツールは未成熟のため、原始的に定点観測する。

1. 主要50クエリリストを作成(05章の各記事の狙いクエリ+難症例の症状語)
2. 毎月同条件で以下を記録: Google AI Overview(表示有無/引用元に本メディアが入るか)、Google AIモード、ChatGPT(検索有効)、Perplexity
3. スプレッドシートに (クエリ × プラットフォーム × 引用有無 × 引用された記事) を記録
4. 引用されたクエリ→同型の記事を横展開 / 引用されないクエリ→競合の引用元を分析し、構造(表・定義文・出典)の差分を埋める

## 7. やらないこと

- 検索ボリューム順のキーワード選定(汎用KWに吸い寄せられる構造的な罠)
- AI量産記事・リライトツールによる水増し(Helpful Content的に致命傷)
- 外部リンク購入・相互リンク集・ディレクトリ登録
- 公式サイトとの同一テーマ重複出稿(01章5節)
- 順位レポートを主KPIにすること(見るのは引用・指名検索・相談。08章)
